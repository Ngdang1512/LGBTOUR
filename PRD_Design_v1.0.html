SaigonAudioTour — Product Design Document

Thiết kế hệ thống thuyết minh du lịch tự động cho tuyến xe buýt 2 tầng Hop-on Hop-off tại Quận 1, TP.HCM. Tài liệu bao gồm toàn bộ use case, kiến trúc, data model, sequence diagrams, activity diagrams, state diagrams và API spec.

Version 1.0 — Thiết kế từ đầu (Greenfield) | Ngày: 2026-05-13

ASP.NET Core 10 EF Core + SQL Server SignalR Realtime PWA + MAUI VNPay Payment RBAC + 2FA OpenAPI 3.0
1
Product Scope

Tổng quan & Mục tiêu sản phẩm

Hệ thống tự động phát thuyết minh âm thanh khi du khách đến gần điểm tham quan (POI), kết hợp quản trị nội dung (CMS), thanh toán subscription, và giám sát realtime.

🎯 Business Goals

  • Tăng mức độ tương tác audio tại từng POI (target: >70% playback rate)
  • Tăng tỷ lệ chuyển đổi Free → Premium (target: >15%)
  • Giảm thao tác thủ công của đội vận hành tour
  • Cung cấp dữ liệu analytics để tối ưu nội dung & tuyến đường

✅ Success Metrics

  • Narration auto-play trigger thành công trong <1s sau khi enter geofence
  • Webhook VNPay xử lý thành công >99.9%
  • Activity event lan truyền tới Admin dashboard <200ms (SignalR)
  • API response P95 <300ms

📍 Phạm vi vận hành

  • Tuyến xe buýt 2 tầng Hop-on Hop-off, Quận 1
  • 15–20 POI điểm dừng & điểm tham quan
  • Hỗ trợ đa ngôn ngữ: Tiếng Việt (vi) và Tiếng Anh (en)
  • Client: PWA (trình duyệt di động), MAUI mobile app

🚫 Ngoài phạm vi

  • Đặt vé tàu/xe trực tuyến
  • Tích hợp bản đồ bên thứ 3 (Google Maps)
  • Chat / support trong app
  • Multi-tenant (nhiều công ty tour)

Actors & Use Cases

Tác nhân và ca sử dụng

Hệ thống có 3 nhóm tác nhân chính: Du khách (Free/Premium), Nhân viên quản trị (theo phân quyền), và Hệ thống tích hợp.

👤 Tourist (Free)

  • Đăng ký / đăng nhập
  • Xem danh sách tour & POI
  • Phát narration cơ bản (giới hạn)
  • QR login trên thiết bị khác
  • Kích hoạt 2FA

👑 Tourist (Premium)

  • Tất cả quyền Free
  • Auto-play narration không giới hạn
  • Truy cập nội dung premium
  • Multi-language narration
  • Offline mode (cached audio)

✏️ Admin (Editor)

  • CRUD POI, Tour, Narration
  • Upload ảnh & audio
  • Giám sát activity realtime

⚙️ Admin (Super)

  • Tất cả quyền Editor
  • Xem analytics dashboard
  • Quản lý users & roles
  • Cấu hình hệ thống

Biểu đồ tuần tự — Key Flows

Seq 6.1 — GPS Geofencing → Auto-play Narration
sequenceDiagram
  participant U as Tourist (PWA)
  participant GPS as Browser GPS API
  participant API as API Server
  participant DB as Database
  participant Hub as ActivityHub (SignalR)
  participant Adm as Admin Dashboard

  GPS-->>U: watchPosition callback (lat, lng)
  U->>U: debounce 5 seconds
  U->>API: POST /api/activity/location {lat, lng, userId, timestamp}
  API->>DB: SELECT pois WHERE isActive=true
  DB-->>API: All active POIs
  API->>API: Calculate distance(user, each POI)
  API->>DB: INSERT UserLog {type: GpsUpdate, lat, lng}

  alt POI match found (distance <= radius)
    API->>DB: SELECT narration WHERE poiId=? AND lang=? AND isPremium<=userTier
    DB-->>API: Narration record
    API->>DB: INSERT UserLog {type: PoiEntered, poiId}
    API-->>U: 200 { triggered: true, poi, narration }
    U->>U: HTML5 Audio.play(narration.audioUrl)
    U->>Hub: SignalR emit("UserAtPoi", {userId, poiId, timestamp})
    Hub->>Hub: Broadcast to "admin" group
    Hub->>Adm: Push event UserAtPoi
    Adm->>Adm: Update radar map marker
  else No POI match
    API-->>U: 200 { triggered: false }
  end

Hình 6.1 — Luồng chính của hệ thống: GPS → API → Narration trigger → Admin realtime update.

Seq 6.2 — User Register & Login (với 2FA)
sequenceDiagram
  participant C as Client
  participant API as API Server
  participant DB as Database

  rect rgb(230, 240, 255)
    Note over C,DB: Registration Flow
    C->>API: POST /api/auth/register {email, password, fullName}
    API->>DB: SELECT AppUser WHERE email=?
    DB-->>API: null (not exists)
    API->>API: BCrypt.HashPassword(password)
    API->>DB: INSERT AppUser {email, hash, status: Free}
    DB-->>API: Created user
    API->>API: GenerateJWT(userId) + GenerateRefreshToken()
    API-->>C: 201 { userId, accessToken, refreshToken }
  end

  rect rgb(230, 255, 235)
    Note over C,DB: Login Flow (2FA Enabled)
    C->>API: POST /api/auth/login {email, password}
    API->>DB: SELECT AppUser WHERE email=?
    DB-->>API: User record
    API->>API: BCrypt.Verify(password, hash)
    alt Password invalid
      API-->>C: 401 { error: "Invalid credentials" }
    else Password valid & 2FA enabled
      API->>API: Generate tempToken (short-lived 3min)
      API-->>C: 200 { requiresTwoFactor: true, tempToken }
      C->>API: POST /api/auth/2fa/verify {tempToken, totpCode}
      API->>API: VerifyTOTP(user.twoFactorSecret, totpCode)
      alt TOTP valid
        API->>API: GenerateJWT + RefreshToken
        API-->>C: 200 { accessToken, refreshToken }
      else TOTP invalid
        API-->>C: 401 { error: "Invalid 2FA code" }
      end
    else Password valid & 2FA disabled
      API->>API: GenerateJWT + RefreshToken
      API-->>C: 200 { accessToken, refreshToken }
    end
  end

Hình 6.2 — Register/Login với 2FA TOTP. tempToken chỉ sống 3 phút để tránh timing attack.

Seq 6.3 — VNPay Subscription Payment
sequenceDiagram
  participant U as Tourist
  participant API as API Server
  participant DB as Database
  participant VN as VNPay Gateway

  U->>API: POST /api/payments/vnpay/create {planId}
  API->>DB: SELECT SubscriptionPlan WHERE id=planId
  DB-->>API: Plan {price, durationDays}
  API->>DB: INSERT PaymentTransaction {status: Pending, orderId: uuid}
  API->>API: Build VNPay params + HMAC-SHA512 sign
  API-->>U: 200 { paymentUrl: "https://sandbox.vnpayment.vn/..." }

  U->>VN: Browser redirect to paymentUrl
  U->>VN: User enters card/banking details
  VN->>VN: Process payment

  par VNPay IPN (Webhook)
    VN->>API: POST /api/payments/vnpay/webhook {vnp_ResponseCode, vnp_SecureHash, ...}
    API->>API: Recalculate HMAC-SHA512, compare with vnp_SecureHash
    alt Signature valid & ResponseCode = "00"
      API->>DB: UPDATE PaymentTransaction SET status=Success
      API->>DB: UPDATE AppUser SET subscriptionStatus=Premium, premiumUntil=now+days
      API-->>VN: 200 { RspCode: "00", Message: "Confirm Success" }
    else Invalid signature
      API-->>VN: 200 { RspCode: "97", Message: "Invalid signature" }
    else Payment failed
      API->>DB: UPDATE PaymentTransaction SET status=Failed
      API-->>VN: 200 { RspCode: "00", Message: "Confirm Success" }
    end
  and VNPay Return (User redirect)
    VN->>U: Redirect to /payments/vnpay/return?vnp_ResponseCode=00&...
    U->>API: GET /api/payments/vnpay/return {vnp_TxnRef, vnp_ResponseCode}
    API->>DB: SELECT PaymentTransaction WHERE orderId=vnp_TxnRef
    DB-->>API: Transaction record
    API-->>U: 200 { success: true, message: "Thanh toán thành công!" }
  end

Hình 6.3 — VNPay flow với 2 luồng song song: IPN webhook (server-to-server) và Return URL (redirect người dùng).

sequenceDiagram
  participant B as Browser / TV Screen

  API-->>B: 200 { token, qrData: "saigontour://qr/{token}" }
  B->>B: Render QR code from qrData
  B->>Hub: SignalR subscribe channel "qr.{token}"

  loop Poll every 2s (or wait for SignalR push)
    B->>API: GET /api/qr/status/{token}
    API-->>B: { status: "Pending" }
  end

  M->>M: Camera scan QR code
  M->>API: POST /api/qr/scan/{token} {Authorization: Bearer userJwt}
  API->>API: Verify user JWT, extract userId
  API->>DB: UPDATE QrLoginToken SET status=Scanned, userId=userId
  API-->>M: 200 { message: "Confirmed. Browser will log in." }
  API->>API: Generate new JWT pair for this session
  API->>Hub: Publish to "qr.{token}" { event: "LoginConfirmed", accessToken, refreshToken }
  Hub->>B: Push { event: "LoginConfirmed", accessToken, refreshToken }
  B->>B: Store tokens in localStorage, redirect to home

Hình 6.4 — QR Login: Token sống 5 phút, single-use. Browser đợi SignalR push để tránh polling liên tục.

State Diagrams

Biểu đồ trạng thái

3 state machines quan trọng trong hệ thống.

State 8.1 — User Subscription
stateDiagram-v2
  [*] --> Free : Đăng ký tài khoản
  Free --> PendingPayment : Khởi tạo mua gói
  PendingPayment --> Premium : Webhook thành công
  PendingPayment --> Free : Thanh toán thất bại / Huỷ
  PendingPayment --> Free : Timeout 15 phút
  Premium --> Expired : premiumUntil < now (cron job)
  Premium --> PendingPayment : Gia hạn trước khi hết
  Expired --> PendingPayment : Mua lại
  Expired --> Free : Không gia hạn

Hình 8.1 — State machine subscription. Cron job chạy hàng giờ để check expiry.

State 8.2 — Payment Transaction
stateDiagram-v2
  [*] --> Pending : Tạo order
  Pending --> Success : IPN webhook OK
  Pending --> Failed : IPN webhook FAIL
  Pending --> Expired : Timeout 15 phút
  Failed --> [*] : Kết thúc
  Expired --> [*] : Kết thúc
  Success --> Refunded : Admin hoàn tiền
  Refunded --> [*] : Kết thúc

Hình 8.2 — State machine giao dịch thanh toán. Timeout là 15 phút theo quy định VNPay.

State 8.3 — POI Proximity (GPS Tracking)
stateDiagram-v2
  [*] --> Idle : GPS được bật
  Idle --> Approaching : Khoảng cách < 2× radius
  Approaching --> Inside : Khoảng cách ≤ radius
  Inside --> Triggered : Auto-play khởi động
  Triggered --> Playing : Audio đang phát
  Playing --> Inside : Phát xong
  Inside --> Exiting : Khoảng cách > radius
  Exiting --> Idle : Khoảng cách > 2× radius
  Approaching --> Idle : User đi ngược lại
  Idle --> [*] : GPS tắt
  note right of Triggered
    Chỉ trigger 1 lần/POI/session
    Không trigger lại nếu vào lại
    trong cùng session
  end note

Hình 8.3 — State machine theo dõi khoảng cách user–POI. Hysteresis zone (2×radius) tránh trigger liên tục khi user ở ranh giới.
